# KP Studio — adoption requirements

Owner: S9. Date: 2026-10-23. Derived from `ADOPTION-AUDIT.md` and `PERSONAS-AND-USE-CASES.md`.
These **add to** `docs/REQUIREMENTS-KP-STUDIO.md` (R-ids); where an R-id already covers a
need, this document references it instead of duplicating. Priorities: **Must** = needed for
the profile to adopt at all · **Should** = planned, may slip a phase with a PO decision ·
**Could** = backlog. Target phase matches the phases in `docs/REQUIREMENTS-KP-STUDIO.md`.

Multimodal input (images, binaries, datasets as model inputs — audit F5) is **not** given a
new A-id here: it is a provider/kernel capability already implied by the capability sheets
(`modalities: [text, image, …]` in `packages/providers/descriptors`) and spec §3.2. It is
raised as WI-S2-01 so S2/S1 schedule it; without it, design/RE/data/GIS stay ◐.

Proof points to add to the benchmark's list (`docs/REQUIREMENTS-KP-STUDIO.md` §"Proof
points"): share of non-software first-runs that reach a useful artifact in 10 minutes
(target ≥ 80 % across profiles 2–18), and number of community packs that load without a code
change (target: unbounded — it must never require one).
